# Component lifecycle

## Experimental

The contract is still being discovered. Consumers should expect breaking changes.

## Beta

The public contract is documented and exercised by a realistic consumer. Known security, compatibility, or operational gaps are explicit. Breaking changes remain possible with migration notes.

## Stable

The component is documented, contract-tested, integration-tested, metadata-complete, migration-safe, and reviewed for risks appropriate to its domain. Breaking changes require a major version.

## Deprecated

The component remains available for a documented period. Its manifest and README identify the replacement and migration path. Removal happens only in a major release.

Semantic versions apply per component. Registry schema changes are versioned independently through `schemaVersion`.
